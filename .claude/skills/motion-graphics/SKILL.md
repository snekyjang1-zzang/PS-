# 모션그래픽 제작 순서

작업 전에 프로젝트 루트의 CLAUDE.md를 읽는다. 명령은 전부 `python mgp.py ...`이다.
**담당자 확인 지점은 네 곳**이다: ⓪ 브리프(무엇을 만들지), ⓪-C 그림 스타일 시안(3장), ③ 구간 계획 + 에셋 목록(돈이 나가기 전), ⑥ 첫 렌더 결과(앞 1~2분). 그 외에는 멈추지 않고 진행한다.

**처음 받은 폴더라면** 순서는: 설치(`python mgp.py setup`) → API 키 등록(① 참고) → 채널 프로필 → **그림 스타일 정하기** → 첫 영상.

## ⓪ 먼저 물어볼 것 — 채널 프로필과 영상 브리프
이 키트를 쓰는 사람마다 채널, 주제, 원하는 화면이 다르다. **앞 영상이나 예시의 스타일을 그대로 가정하지 않는다.** 만들기 전에 아래를 확인한다.
`python mgp.py brief <이름>`이 아직 안 채워진 항목을 보여 준다.

### 묻는 방법
- **대본을 먼저 읽는다.** 대본에서 알 수 있는 것(주제, 장르, 무거운 구간, 숫자와 고유명사)은 묻지 말고 추정해서 "이렇게 이해했다"고 보여 주고 확인만 받는다.
- 한 번에 3~4개씩, **선택지와 추천안을 붙여서** 묻는다(질문 도구가 있으면 그것으로). 서술형으로 길게 묻지 않는다.
- "알아서 해줘"라고 하면 추천안으로 정하고, 정한 값을 한 번에 요약해 보여 준다.
- 답은 바로 파일에 적는다. 채널 전체에 해당하면 `brand/channel.json`, 이 영상만이면 `projects/<이름>/brief.md`.
- 채널 프로필은 **처음 한 번만** 묻는다(`"filled": true`로 바꿔 둔다). 두 번째 영상부터는 영상 브리프만 묻는다.
- 진행 중 받은 수정 요청("글자가 너무 많다", "더 느리게")이 채널 전체에 해당하면 프로필에도 옮겨 적어 다음 영상에서 반복되지 않게 한다.

### A. 채널 프로필 (처음 한 번) → `brand/channel.json`
| 물어볼 것 | 왜 필요한가 | 적는 곳 |
|---|---|---|
| 채널 이름, 주로 다루는 분야 | 화면 소재와 화풍의 출발점 | `channel_name`, `genre` |
| 누가 보는가 | 설명 깊이, 글자 크기, 농담 수위 | `audience` |
| 말투와 분위기 (진지한 다큐 / 가볍고 농담 섞인 / 차분한 튜토리얼) | 연출 속도와 색, 캐릭터 사용량 | `tone` |
| 말풍선 농담을 넣을지 | 대본에 없는 대사를 지어 넣게 되므로 허락이 필요 | `humor` ("넣음" / "안 넣음") |
| 참고 채널이나 참고 화면 (있으면 이미지로) | 말로 설명하기 어려운 "느낌"을 맞추는 가장 빠른 길 | `references` |
| 기본 그림 화풍 | 참고 자료를 보고 제안한 뒤 확인받아 영어 한 문장으로 | `visual_style` |
| 마스코트를 둘지, 둔다면 어떤 캐릭터로 만들지 | 진행자 역할. 키트에는 마스코트가 들어 있지 않다. 원하면 아래 순서로 새로 만든다 | `mascot` |
| 내레이션 (Gemini 목소리 / 일레븐랩스 내 목소리 / 직접 만든 음성 파일) | 음성 단계가 달라진다. 일레븐랩스면 보이스 ID와 API 키를 받는다 | `narration`, `tts` |
| 자막 모양과 전체 속도 | 기본값(어두운 박스, 1.3배 느리게)을 보여 주고 바꿀지만 묻는다 | `style` |
| 실제 사진·그림을 써도 되는지 | 퍼블릭 도메인 자료 사용 허락 | `real_photos` |
| 끝 구독 멘트 문장 | 영상 끝에 음성으로 들어간다. 없으면 넣지 않는다 | `outro_say` |
| 썸네일 형식 (참고 이미지) | 형식은 채널마다 고정이라 한 번만 정한다 | `thumbnail` |
| 피해야 할 것 (표현, 색, 소재) | 같은 지적을 반복받지 않기 위해 | `avoid` |

#### 마스코트 만들기 (담당자가 원할 때만, 유료)
1. **먼저 묻는다**: 마스코트를 둘 것인가? 둔다면 — 어떤 캐릭터(동물, 사물, 사람), 성격(시큰둥한, 다정한, 엉뚱한 등), 옷과 소품, 참고 이미지가 있는가. "알아서"라고 하면 채널 분야와 분위기에 맞는 방향 3가지를 글로 제안한다.
2. `python mgp.py new 마스코트` → `templates/mascot_assets_template.json`을 그 프로젝트의 `assets.json`으로 복사해 후보 3종의 프롬프트를 쓴다. 다른 채널이나 작품의 캐릭터를 따라 만들지 않는다.
3. 후보 3종을 생성해 한 장으로 보여 주고 고르게 한다. 마음에 드는 것이 없으면 의견을 받아 다시 만든다.
4. 고른 후보를 `refs`로 넣어 포즈 세트(point, shrug, shock, think, peek, facepalm, ew)를 생성한다. 필요하면 영상 주제에 맞는 복장 버전도 같은 방식으로 만든다.
5. `brand/<이름>_<포즈>.png`로 복사한다(전신은 `<이름>_full.png`, 전신의 위쪽 절반을 잘라 `<이름>_idle.png`). 팔과 몸 사이에 흰 배경 조각이 남았는지 확인한다.
6. `brand/channel.json`에 `"mascot": "<이름>"`을 적고, 말풍선이 입에서 나오도록 `"mascot_beak": {"point": [가로, 세로], ...}`에 포즈별 입 위치(그림 안 비율, 왼쪽을 볼 때)를 적는다.
7. 마스코트를 두지 않으면 `mascot`을 비워 둔다. 장면 코드의 `mascot(...)`, `host(...)`는 아무것도 그리지 않는다.

### C. 그림 스타일 정하기 (담당자가 직접 정한다 — 처음 한 번, 영상마다 바꿔도 된다)
그림 스타일은 키트가 정해 주지 않는다. **담당자가 고른 스타일로 시안 3장을 만들어 승인받은 뒤**에 본 에셋을 만든다. 예시나 앞 영상의 그림체를 기본으로 가정하지 않는다.
1. **어떻게 정할지 묻는다** (셋 중 하나, 섞어도 된다)
   - (가) **참고 이미지를 준다**: 원하는 그림체의 이미지 1~5장을 `brand/style_refs/` 폴더에 넣어 달라고 한다(채팅에 붙여 줬다면 그 파일을 이 폴더에 저장한다). 가장 정확하다.
   - (나) **말로 설명한다**: "두꺼운 먹선에 탁한 색, 만화풍", "수채화 그림책", "80년대 애니 셀화", "판화", "3D 클레이" 등.
   - (다) **맡긴다**: 대본의 장르와 분위기를 보고 서로 뚜렷이 다른 방향 3가지를 글로 제안해 고르게 한다(위 "장르별 출발점" 참고).
   - 같이 묻는다: **사람을 어떻게 그릴지**(특정 캐릭터 얼굴로 통일 / 얼굴 없는 단순한 인물 / 실루엣 / 사실적인 인물), **색 분위기**(밝게 / 어둡게 / 바랜 색).
2. **화풍 문장을 쓴다**: 참고 이미지는 직접 열어 보고(Read) 선의 굵기와 색, 색감, 명암 방식, 질감, 인물을 그리는 방식을 영어 한두 문장으로 옮긴다. 이 문장이 `assets.json`의 `style`이 되어 모든 프롬프트에 붙는다. 작가 이름이나 작품 제목을 넣지 말고 그리는 방식을 묘사한다.
3. **스타일 시안 3장** (유료, 약 3장 값): `python mgp.py new 스타일시안` → `templates/style_test_assets.json`을 그 프로젝트의 `assets.json`으로 복사해 채운다 — 이 영상의 대표 인물 1명(`style_char`), 대표 장소 1곳(`style_bg`, 사람 없이), 대표 소품 1개(`style_prop`). 참고 이미지가 있으면 `{"id": "ref_1", "kind": "ref", "file": "brand/style_refs/파일명"}`으로 등록해 이 3장의 `refs`에만 넣는다. `assets 스타일시안 --yes` → `out/_contact_sheet.jpg`를 담당자에게 보여 준다.
4. **승인받는다.** "선을 더 굵게", "색을 더 밝게" 같은 의견이 오면 화풍 문장을 고쳐 그 3장만 다시 만든다. 여기서 맞춰야 뒤에서 백 장을 다시 만들지 않는다.
5. **확정한 스타일을 기록한다**: 화풍 문장은 `brand/channel.json`의 `visual_style`(새 프로젝트의 기본값)에, 승인된 3장은 `brand/style_char.png`, `brand/style_bg.png`, `brand/style_prop.png`로 복사한다. 본 영상의 `assets.json`에서는 이 3장을 `{"id": "anchor_char", "kind": "ref", "file": "brand/style_char.png"}`처럼 등록해 `refs`로 쓴다.
6. **이후 규칙 — 참고 이미지는 화풍만 빌린다**
   - 담당자가 준 참고 이미지를 **장면에 그대로 넣지 않는다.** 본 에셋의 `refs`에도 넣지 않는다: 참조로 넣으면 그림체뿐 아니라 구도, 인물, 소품까지 그대로 베껴져 나온다. 본 에셋의 참조는 승인된 시안(`anchor_*`)이나 그 뒤에 만든 내 에셋만 쓴다.
   - 참고 이미지와 같은 내용을 그려야 해도 구도와 소품을 다르게 잡는다.
   - 다른 채널의 고유 캐릭터나 실존 인물의 얼굴을 따라 그리지 않는다. 그림체(선, 색, 질감)를 참고하는 것까지만 한다.

### B. 영상 브리프 (영상마다) → `projects/<이름>/brief.md`
| 물어볼 것 | 비고 |
|---|---|
| 대본 (또는 이미 만든 음성 + 자막 파일) | 필수. 없으면 시작하지 않는다 |
| 주제 한 줄과 장르 | 대본에서 추정하고 확인만 |
| 시청자가 가져갈 한 문장 | 구간을 나눌 때와 썸네일의 기준 |
| 읽는 법이 애매한 낱말 | 숫자, 영어, 약어, 고유명사 |
| 꼭 보여 줄 자료 | 실제 사진·그림, 그래프와 그 출처, 시연할 웹사이트 주소 |
| 민감한 구간과 다루는 방식 | 죽음, 범죄, 실존 인물, 정치·종교. 대본에서 찾아 "이 구간은 담담하게 처리하겠다"고 제안 |
| 이 영상만 다르게 할 화면 방향 | 없으면 채널 기본 |
| 이미지 예산 | 예상 장수를 먼저 알려 주고 상한과 품질을 정한다 |
| 썸네일이 필요한지, 문구 방향 | |

### 장르별 출발점 (대본을 읽고 제안할 때)
| 장르 | 화면의 주 소재 | 화풍 제안 | 놓치기 쉬운 것 |
|---|---|---|---|
| 역사 | 지도, 연표, 당시 그림·문서, 인물 | 판화·고지도·양피지 | 사건의 한 장면(병, 전투)만 크게 쓰면 다른 장르로 보인다. 시대와 장소가 보이게 |
| 과학·의학 | 단면도, 과정 도해, 확대 그림, 의인화 캐릭터 | 도감 일러스트 | 혐오감을 주는 묘사 수위. 수치에는 출처 |
| 경제·비즈니스 | 숫자 올리기, 비교 막대, 흐름도, 사람 아이콘 | 플랫 벡터, 밝은 배경 | 대본에 없는 배수·퍼센트를 계산해 넣지 않는다 |
| IT·튜토리얼 | 웹 화면 녹화, 단계 표시, 채팅 UI | 깔끔한 UI 스타일 | 한 문장에 한 곳만 보여 준다. 로그인은 사용자가 직접 |
| 시사·사회 | 기사·문서 카드, 그래프, 지도 | 차분한 톤 | 실존 인물은 실제 얼굴을 만들지 않는다. 사실과 의견 구분 |
| 인물 | 연표, 인물 컷아웃, 장소 | 주제 시대에 맞춤 | 실존 인물 묘사, 인용문 출처 |

**대표 그림은 장르에서 고른다.** 썸네일과 첫 화면은 영상에서 가장 자극적인 세부가 아니라 "이게 어떤 콘텐츠인지" 알려 주는 소재로 잡는다(역사 영상에 손 클로즈업을 쓰면 의학 영상으로 보인다).

### 브리프 요약 → 확인
채운 뒤 다섯 줄 안팎으로 요약해 보여 주고 확인받는다: 주제와 장르 / 화풍과 마스코트 / 음성 / 민감 구간 처리 / 예상 이미지 장수와 비용 발생 단계.

## ① 준비
1. `python mgp.py doctor`로 설치와 API 키 유무를 확인한다. 설치가 안 돼 있으면 `python mgp.py setup`(몇 분 걸린다)을 실행한다.
   - **API 키**: 담당자가 키가 적힌 txt 파일을 주면 `python mgp.py keys --from "<그 파일 경로>"`로 등록한다. **그 파일을 직접 열어 읽지 않는다**(키 값이 대화에 남는다). 명령이 어떤 키를 찾았는지만 알려 준다. 등록 뒤에는 txt 파일을 지우라고 안내한다. 파일에 일레븐랩스 보이스 ID가 있으면 채널 기본 목소리로 들어간다.
   - 일레븐랩스 키가 없으면: 목소리는 Gemini로 만들고, 배경음·효과음 생성(`sound gen`)은 건너뛴다(담당자가 음악 파일을 주면 `projects/<이름>/sound/music_main.mp3`로 넣어 `sound mix`만 쓸 수 있다).
2. `python mgp.py new <이름>`으로 폴더를 만든다. 이름은 짧게(예: `흑사병`, `ep01`). 채널 프로필의 목소리, 자막, 속도, 화풍이 기본값으로 들어간다.
3. 담당자가 채팅에 붙여 준 대본을 `projects/<이름>/input/script.txt`에 저장한다. 내용은 고치지 않는다.
   - `#`으로 시작하는 줄과 `[화면: ...]` 같은 한 줄 지시문은 음성에 들어가지 않는다.
   - 숫자, 영어, 약어의 읽는 법이 애매하면 담당자에게 묻는다(예: "1348년", "AI").

## ② 음성과 자막
1. 대본 글자 수와 문장 수를 알리고 `python mgp.py tts <이름>`을 실행한다.
2. `python mgp.py cues <이름>`으로 자막 번호와 시각을 확인한다. 이후 모든 타이밍의 기준이다.
3. 담당자에게 `input/narration.wav`를 들어 보라고 안내한다. 고칠 문장이 있으면 대본을 고치고 `tts`를 다시 실행한다(바뀐 문단만 새로 합성된다).
   - **음성이 바뀌면 자막 번호와 시각이 달라진다.** 장면을 만든 뒤에 대본을 고쳤다면 `status`로 장면 구성을 다시 확인한다.
4. 목소리와 말투는 `project.json`의 `tts`에서 바꾼다. `style`은 짧게(예: "calm documentary narration") 쓰거나 비워 둔다.
5. **목소리는 처음부터 끝까지 같아야 한다.** 그래서 문단 단위로 합성한다(`tts.unit: "paragraph"`, 기본). 문장마다 따로 합성하면(`"sentence"`) 문장 사이에서 목소리 높이가 3~5반음씩 달라져 다른 사람처럼 들린다.
   - `tts`는 문단끼리 높이·음색·속도를 재서 벗어난 문단을 자동으로 다시 합성하고, 결과를 `input/voice_report.json`에 남긴다. 실행 결과에 "남은 문제 0개"가 나왔는지 확인하고, ⚠ 표시가 있으면 `tts`를 한 번 더 실행한다.
   - 대본의 빈 줄이 문단 경계다. 한 문단이 60초를 넘지 않게 나눈다(20문장 안팎까지).
   - 말이 느리거나 빠르면 `style`에 템포를 적거나(예: "평소보다 약간 빠른 템포") `tts.tempo`(예: 1.07)로 전체 속도를 조절한다. 음높이는 변하지 않는다.
6. **일레븐랩스 음성은 쉼이 길다**(전체의 20~25%). `tts` 뒤에 `python mgp.py trim <이름> --tempo 1.08`로 문장 사이 쉼을 0.3초, 문단 사이를 0.7초로 줄이고 8% 빠르게 한다(값은 담당자 취향에 맞춘다). 자막 시각도 같이 옮겨지므로 **장면을 만들기 전에** 한다.
7. **받아쓰기 검사**: `python mgp.py listen <이름>` — 음성을 받아써서 대본과 다르게 들린 곳만 보여 준다. 고유명사와 숫자 근처의 차이를 확인하고, 잘못 읽었으면 대본 표기나 `tts.say_as`를 고쳐 그 문단만 다시 만든다. 소리가 같은 표기 차이나 구간 경계의 겹침은 넘어간다.

## ③ 구간 계획 + 에셋 목록 → 담당자 확인
자막을 읽고 영상 전체를 장면으로 나눈다. **완성 영상이므로 모든 자막이 어느 장면에든 속해야 한다.**
1. 장면 표를 만든다: 장면 번호, 자막 구간, 시각, 화면 내용, 쓰는 에셋, 종류.
   - **설명 장면**: 메커니즘, 이동, 비교, 숫자 → 지도, 도해, 카드, 그래프
   - **인물·사건 장면**: 컷아웃 캐릭터 + 이름표, 도장
   - **시연 장면**: 실제 웹사이트 화면이 필요한 곳 → ⑤에서 녹화
   - **무거운 구간**: 죽음, 범죄 → 페이드만, 담담하게
   - 장면 하나는 보통 자막 3~8개(10~40초). 주제가 바뀌는 곳에서 끊는다.
   - 요령: **기준 배경 1~2장**(지도, 인체도, 책상 등)을 정해 여러 장면에서 다시 쓰면 적은 에셋으로 통일감이 난다.
2. `assets.json`을 작성한다(형식은 `tools/assets.py` 상단 참고).
   - `style`: 영상 전체의 공통 그림 스타일을 영어 한 문장으로. 모든 프롬프트에 자동으로 붙는다. 흔한 매끈한 AI 그림체보다 영상 주제에 맞는 뚜렷한 화풍을 고른다.
   - **실제 사진·그림**을 쓰려면 `{"id": "p_xxx", "kind": "photo", "src": "commons:<위키미디어 공용 파일명>", "treat": "print"}`. 내려받아 판화풍 질감의 카드로 만들어 준다(무료). 퍼블릭 도메인이 아니면 거부하므로 담당자에게 확인받는다. 출처는 `assets/_credits.json`에 쌓이고, 화면에는 아주 작게 표기한다. `treat`: 그림은 `print`(바랜 색), 흑백 사진은 `engrave`.
   - 사물과 캐릭터의 화풍을 다르게 쓰려면 맨 위 `"styles": {"ch": "..."}`에 정의하고 에셋에 `"style": "ch"`. 설명형 영상은 역할(균, 면역세포, 왕, 의사 등)을 **얼굴 없는 단순한 캐릭터**로 의인화하면 전달이 쉽다. 다른 채널의 고유 마스코트는 따라 만들지 않는다.
   - 작은 것 여러 개(장기 4종, 행성 3개)는 한 장에 띄워 그리게 하고 `"split": true`로 나눈다(`<id>_0`, `<id>_1` ...).
   - 여러 번 나오는 인물은 **기준 모습 1장을 먼저** 만들고, 나머지 포즈는 전부 그 에셋을 `refs`로 참조한다(얼굴과 옷이 유지된다).
   - `background`: 16:9 전면 배경 / `cutout`: 캐릭터, 아이콘, 소품(흰 배경으로 생성 후 자동 제거) / `texture`: 번짐, 얼룩
   - 서 있는 인물처럼 세로로 긴 컷아웃은 `"size": {"width": 1024, "height": 1536}`을 주면 더 크게 나온다.
   - 같은 구도에서 상태만 바꾼 배경은 `"edit_of": "원본id"` + `"Only change: ..."` (크로스페이드용)
   - 같은 캐릭터의 다른 포즈는 `"refs": ["원본id"]` + `"same character, ..."`
   - 프롬프트는 영어로, 대상 하나만 구체적으로. 글자, 숫자, 화살표, UI, 그래프, 채팅창은 에셋으로 만들지 않고 엔진으로 그린다("no text"는 자동으로 붙는다).
   - 실존 인물은 "generic ..."으로 쓴다(실제 얼굴을 재현하지 않는다).
   - id는 `bg_`, `c_`, `ic_`, `tx_` 접두사 + 영문 이름.
   - **참조(refs)는 그 장면의 시대·장소에 맞는 것만**: 여러 시대나 여러 인물이 한 장에 든 그림을 참조로 넣으면 배경에 엉뚱한 인물이 섞여 나온다(중세 전장에 로마 병사). 배경을 만들 때는 그 시대의 인물 **한 명짜리** 컷아웃이나 `anchor_*`를 참조로 쓰고, 프롬프트 끝에 "Every person in the picture belongs to this one time and place"를 붙인다.
   - **사람 없는 배경**(지도, 빈 종이, 빈 방)은 공통 화풍 문장에 "사람을 이렇게 그린다"가 들어 있으면 사람이 그려져 나온다. 그런 항목에는 에셋별 `"style"`로 화풍 문장 + "Absolutely no people, no characters, no faces"를 따로 준다.
   - 긴 영상(10분 이상)은 **캐릭터·소품은 컷아웃으로, 배경은 사람 없이 따로** 만들어 코드로 조합하면 같은 에셋을 여러 컷에 다시 쓸 수 있다. 한 번만 나오는 정경은 사람까지 그린 전면 배경 한 장으로 만든다. 10분에 60~80장이 기준이다.
3. `python mgp.py assets <이름>`(`--yes` 없이)으로 목록을 출력하고, **장면 표와 에셋 목록(개수, 품질)을 담당자에게 보여 승인받는다.**

## ④ 에셋 생성
1. 승인 후 `python mgp.py assets <이름> --yes`. 실패한 것은 같은 명령을 다시 실행하면 그것만 다시 시도한다.
2. `out/_contact_sheet.jpg`를 **직접 열어** 확인한다: 투명 처리, 잘림, 글자가 들어갔는지, 스타일이 서로 맞는지.
   - **배경은 크게 띄워 본다**: 다른 시대·다른 장면의 인물이나 물건이 섞였는지, 담당자의 참고 이미지와 구도가 똑같지 않은지.
   - 컷아웃 안쪽에 흰 배경 조각이 남았는지(고리 안, 팔과 몸 사이, 삼각대 다리 사이), 흰 옷·종이가 잘려 나가지 않았는지.
3. 마음에 안 드는 것은 프롬프트를 고치고 `python mgp.py assets <이름> <id> --yes`로 그것만 다시 만든다.
4. 배경 위에 핀이나 라벨을 놓을 곳은 `python mgp.py grid <이름> <id>`로 좌표를 읽어 둔다.

## ⑤ 웹 시연 녹화 (필요한 장면만)
목표는 "화면을 보여 주는 것"이 아니라 **"이 문장에서 시청자가 어디를 봐야 하는지"를 분명히 하는 것**이다.
1. 먼저 문장별로 **보여 줄 대상을 하나씩** 정한다(이 문단, 이 숫자, 이 버튼). 한 문장에 한 곳. 대상이 없는 문장은 전체 화면으로 둔다.
2. 사이트를 살펴 그 대상의 선택자를 정한다(브라우저 도구가 있으면 그것으로, 없으면 대본을 짧게 써서 시험 녹화).
3. `templates/capture_template.py`를 `captures/<녹화이름>.py`로 복사해 작성한다.
   - 처음 1~1.5초는 `h.pause()`로 전체 화면(어떤 사이트인지 보여 준다).
   - 보여 줄 대상마다 `h.focus(선택자, hold=2.5)`. 제목 전체나 본문 전체처럼 넓은 것 말고 **내레이션이 말하는 바로 그것**을 가리킨다.
   - 누르는 동작은 `h.click`, 입력은 `h.type`. 클릭하면 화면이 바뀌므로, 결과에서 볼 곳을 이어서 `h.focus`로 가리킨다.
   - **보여 줄 곳이 아니면 마우스를 움직이지 않는다.** `h.hover`, `h.move`로 이곳저곳 훑지 않는다. 카메라 이동은 10초에 2~3번이면 충분하다.
   - 스크롤이 필요하면 먼저 `h.park()`(링크 미리보기 팝업 방지). 스크롤 중에는 전체 화면이 된다.
   - 내레이션과 맞출 지점마다 `h.mark('라벨')`. 기다릴 때는 `h.pause()`만 쓴다.
   - 길이는 해당 자막 구간보다 조금 길게 잡는다(장면에서 필요한 부분만 쓴다). 녹화 앞부분의 빈 화면은 장면에서 `cap_mark`, `cap_click`으로 건너뛴다.
4. `python mgp.py record <이름> <녹화이름>` → `out/_capture_<녹화이름>.jpg`를 열어 확인한다. 페이지는 1280x720 크기로 열려 2560x1440으로 찍힌다(줌인해도 선명).
5. 장면에서는 `wall(C)` + `screen(C, '<녹화이름>', 영상시각, ...)`. 대상으로 줌인해 멈추고 테두리로 강조하는 것은 자동이다. `probe`로 **강조 테두리가 실제로 그 대상 위에 있는지**, 글자가 읽히는지 확인한다(`examples/v2_sample/scenes/s03.py`).
6. 로그인이 필요하면 담당자에게 `python mgp.py record <이름> --login <주소>`를 실행해 직접 로그인하도록 안내한다.
7. 웹이 아닌 프로그램 화면이 필요하면 담당자가 직접 녹화한 mp4를 `captures/<이름>.mp4`로 넣는다. 이 경우 자동 줌과 강조는 없고 `capture()`로 그대로 넣는다.
8. 넣어 둔 영상을 **소리까지 그대로** 틀어야 하면(다른 도구로 만든 결과물을 보여 줄 때 등) 대본의 그 자리에 `[영상: 이름]` 줄을 넣는다. 내레이션이 그 길이만큼 멈추고, 장면에서 `clip()`으로 그리면 완성본에 영상의 소리가 들어간다 (장면별 확인 영상에는 소리가 안 들어가고 `final`에서만 섞인다).

## ⑥ 장면 제작 → 첫 렌더 확인
1. `templates/scene_template.py`를 `scenes/s01.py`, `s02.py` ... 로 복사해 작성한다. 엔진 함수의 쓰임이 궁금하면 `examples/v2_sample/`(지도 줌인 + 핀 + 도장, 캐릭터 크로스페이드, 웹 녹화 창)을 본다. **예시는 함수 쓰는 법만 참고하고, 화면 구성과 연출은 이 영상의 대본에서 새로 짠다**(예시의 장면을 순서대로 본뜨지 않는다).
2. 연출 원칙
   - 문장이 나오는 순간에 요소가 등장한다(`at`, `atw`). 미리 띄워 두지 않는다.
   - 화면마다 카메라 무빙(줌인, 패닝)이나 요소 움직임을 준다. 완전히 정지한 화면은 만들지 않는다.
   - 텍스트는 짧은 키워드로. 자막과 같은 문장을 화면에 반복하지 않는다.
   - 같은 배경을 다시 쓸 때는 앞에서 쓴 연출과 호응시킨다.
   - **구도를 먼저 정한다**: 큰 글자가 들어갈 자리는 배경이 잔잔한 곳으로 비워 두고, 인물은 한쪽으로 몬다. 글자는 나중에 얹는 것이 아니라 구도의 일부다.
   - **숫자가 핵심이면 숫자를 주인공으로**: 금액, 비율은 화면에서 가장 큰 글자로, 0에서 올라가게(`examples/v2_sample_numbers`의 `count`). 비교는 길이가 값에 정확히 비례하는 막대로 보여 준다. 대본에 없는 배수나 퍼센트를 계산해 덧붙이지 않는다.
   - **빈 화면으로 시작하지 않는다**: 장면 첫 0.2초 안에 첫 요소가 보이게 한다.
   - **글자 크기에 강약을 둔다**: 모든 장면이 같은 크기의 라벨이면 단조롭다. 핵심 한마디는 화면을 채우는 큰 글자로, 나머지는 작은 라벨로.
   - **영상 첫 3초는 가장 강한 화면으로** 시작한다(질문, 반전, 큰 숫자).
   - 인물이 계속 나오면 사이사이 인물 없는 화면(지도, 도해, 웹 화면)을 끼워 리듬을 바꾼다.
3. 호흡(모션 길이) — 너무 빨리 끝나면 화면이 멈춰 보인다
   - 등장은 0.5~0.8초, 선과 화살표는 1.0~1.5초(`draw_on`), 카메라 이동은 1.5~2.5초, 퇴장은 0.3~0.6초.
   - 여러 요소는 한꺼번에 띄우지 말고 0.2초 안팎 간격으로 차례로(`stagger`).
   - **등장이 끝난 뒤에도 움직임을 남긴다**: 점선은 흐르게(`phase=t * 60`), 인물과 사물은 아주 천천히 밀거나 키우고(`alive`), 카메라는 계속 미세하게 줌한다. 2초 넘게 아무것도 안 움직이는 구간을 만들지 않는다.
   - 단, 남기는 움직임은 **한 방향으로 아주 느리게**(초당 몇 px, 몇 초에 2~3%). 왔다 갔다 하거나 빠르면 떨림으로 보인다. `wobble`은 일부러 흔들 때만 쓴다.
   - **시간 예산을 먼저 계산한다**: 모션이 끝나기 전에 다음 요소가 덮거나 사라지게 하면 안 된다. 문장이 짧아 시간이 모자라면 모션을 줄이지 말고 시작을 문장 첫머리로 당긴다. `probe`에서 모션의 끝 시점 프레임도 확인한다.
4. 장면마다 `python mgp.py probe <이름> sNN` → jpg를 **직접 열어** 확인 → 수정. 특정 순간은 `probe <이름> sNN 2.5 4.0`처럼 초를 지정한다.
5. `python mgp.py status <이름>`으로 빠진 자막 구간이 없는지 확인한다.
6. **앞의 2~3개 장면만 먼저**(긴 영상은 첫 1분: `python mgp.py preview <이름>`) `python mgp.py render <이름> s01 s02 s03`으로 렌더해 `out/scenes/`의 영상을 담당자에게 보여 주고, 톤과 속도에 대한 의견을 받는다.
7. 의견을 반영해 나머지 장면을 만들고 `python mgp.py render <이름>`.
8. 렌더가 끝나면 `out/scenes/`의 장면별 미리보기 jpg를 전부 열어 보고, 기준에 못 미치는 장면은 담당자에게 넘기기 전에 다시 만든다. 장면 사이의 색, 글자 스타일, 전환이 서로 어울리는지도 본다.

### 컷아웃 화면 키트 (인물 컷아웃 + 이름표 + 말풍선 + 지도 방식)
배경 위에 캐릭터를 크게 세우고 이름표와 말풍선을 붙이는 방식의 영상은 `templates/shared_cutout.py`를 `scenes/_shared.py`로 복사해 쓴다. 쓰는 문법은 `templates/scene_cuts_template.py`(컷 패턴 모음)에 있다.
- **틀과 예시를 따라 만들지 않는다.** 패턴 모음과 `examples/`는 함수 쓰는 법을 보여 줄 뿐이다. 낱말, 좌표, 컷의 순서, 패턴의 조합을 그대로 옮기면 모든 영상이 똑같아진다.
  - 장면을 쓰기 전에 문단마다 **"이 문장을 무엇으로 보여 주면 가장 잘 전달되는가"**를 한 줄씩 적는다(장면 표). 그림이 먼저고, 패턴은 그다음에 고른다. 맞는 패턴이 없으면 `_shared.py`에 새 요소를 만든다.
  - 같은 패턴(예: 종이 바탕 + 컷아웃 + 큰 낱말)을 세 컷 연속 쓰지 않는다. 그림 한 장, 인물, 도식, 지도, 숫자, 비교를 섞는다.
  - 색, 글자 크기와 굵기, 자막 모양, 바탕은 그 채널과 주제에 맞게 `_shared.py`에서 다시 잡는다. 키트의 기본값은 출발점일 뿐이다.
- **컷으로 쓴다**: 장면 하나(문단 하나쯤) 안에서 자막 한두 개마다 컷을 바꾼다 — `seq(C, t, [(0.0, c1), (A(7), c2), ...])`. 한 화면에 요소를 차례로 쌓지 말고 **한 컷에 하나만 크게**.
- 컷 하나는 한두 줄이다: `pic`(그림 한 장 + 느린 카메라 + 큰 낱말), `port`(반신 인물 + 이름표 + 말풍선), `intro`(지도가 그곳으로 다가가며 지명 표시), `paper`/`dark` 바탕 위에 `ch`(컷아웃) + `W1`(큰 낱말) / `no`(빨간 줄로 지우기) / `tag`(작은 라벨) / `num`(숫자 올리기) / `split2`(좌우 비교) / `arrow`.
- **글자끼리, 글자와 그림이 겹치지 않게**: 두 줄 이상 쌓는 글자는 반드시 `plate`, `place`, `W1(sub=...)`, `T`, `tag`로 놓는다(글자가 실제로 보이는 칸을 재서 놓는다). 글자는 캐릭터의 얼굴과 아래 자막 상자(y 960 아래)를 피한다. 움직이는 캐릭터가 지나갈 자리에 글자를 두지 않는다.
- **2초 넘게 배경만 보이는 컷을 만들지 않는다**: "…무슨 뜻이었을까요" 같은 질문 문장에서 낱말이 뒤늦게 나오도록 걸면 그 앞이 빈다. 컷이 시작될 때(0.1초) 캐릭터나 소품을 먼저 세우고, 낱말을 문장에 맞춘다.
- 자막 모양·글꼴·색은 복사한 `_shared.py`에서 그 영상에 맞게 고친다. 참고 채널이 있으면 **화면을 확대해서** 자막 상자, 글자 테두리, 말풍선 모양을 글자 단위로 확인하고 맞춘다(작은 캡처만 보고 어림하지 않는다).
- **점검은 `python mgp.py check <이름> [장면 ...]`**: 모든 컷의 끝 프레임을 `out/_check_N.jpg`로 모아 준다. 이 그림을 직접 열어 겹침, 잘림, 빈 화면, 자막 가림, 화면 밖으로 나간 글자를 고친 뒤 렌더한다. 오류가 나는 장면과 줄 번호도 알려 준다.

### 배경음과 효과음 (일레븐랩스 키가 있을 때)
1. `templates/sound_template.json`을 `projects/<이름>/sound.json`으로 복사해 고친다: 효과음 5~7종(영어 설명 + 길이), 배경음 1~2곡(분위기를 영어로, 150초 안팎, "Instrumental only"), 어느 구간에 어느 곡을 깔지(`bgm`).
2. 장면 파일 끝에 `SFX = snd(low=[0.0], thud=[A(7)], ...)`로 효과음 시각을 적는다(장면 기준 초). 컷이 바뀔 때와 큰 낱말이 나올 때만, 과하지 않게.
3. `python mgp.py sound <이름> gen`(목록 확인) → 담당자 승인 → `--yes`(유료). 그다음 `python mgp.py sound <이름> mix`(무료, 내레이션보다 약 21dB 작게 깔린다).
4. **장면을 고치거나 음성이 바뀌면 `render` → `sound mix` → `final` 순서로 다시 한다.** `mix`를 빼먹으면 완성본에 옛 소리가 들어가거나 배경음이 빠진다. 실행 결과의 "배경음 구간 N개 · 효과음 N개"를 확인한다.

## ⑦ 완성
0. 끝에 구독 멘트(`outro.py`, CLAUDE.md 참고)를 넣었는지 확인한다. `status`에 outro 줄이 보이면 들어간 것이다. 멘트 문장은 담당자에게 확인받는다.
1. (배경음·효과음을 쓰면 `python mgp.py sound <이름> mix` 먼저) `python mgp.py final <이름>` → `out/<이름>_final.mp4` (자막 포함, 음성 포함). 같은 폴더에 `.srt`도 복사된다.
   - 완성본에서 프레임을 10~20장 뽑아 직접 확인한다(고친 곳, 장이 바뀌는 곳). 움직임과 소리는 직접 확인할 수 없으니 담당자에게 봐 달라고 한다.
2. 마무리 보고: 장면 번호와 시각 표, 근사치로 잡은 것(지도 위치 등), 연출용 임의값, 담당자가 확인할 지점.

## 수정 요청
- "s07에서 ○○ 바꿔줘" → 해당 장면 파일만 고치고 `probe` → `render <이름> s07` → `final`. 다른 장면은 다시 렌더하지 않는다.
- 에셋 교체 → `assets <이름> <id> --yes` 후 `render`(그 에셋을 쓰는 장면만 자동으로 다시 렌더된다).
- 담당자는 "1분 31초에 글자가 겹친다"처럼 **시각으로** 말한다. `status`로 그 시각의 장면을 찾아 고치고, 같은 문제가 다른 장면에도 있는지 `check`로 전부 훑어 함께 고친다.
- 대본 수정 → `tts` → `status`로 구간 확인 → `render` → `final`.

## ⑧ 썸네일 (요청 시)
- 형식은 채널 프로필의 `thumbnail`을 따른다. 정해진 것이 없으면 참고 이미지를 받아 형식부터 정한다(글자 줄 수, 색, 그림 위치).
- 먼저 3가지 안(그림 소재 + 문구)을 글로 제안하고 확인받은 뒤 만든다. 문구는 대본에 있는 내용만.
- **문구는 답을 감춘다.** 범인, 원인, 결론을 썸네일에서 말해 버리면 누를 이유가 없다. 사실 하나를 던지고 의문을 남긴다.
- 그림 소재는 위의 "대표 그림은 장르에서 고른다"를 따른다.
- 1280x720 JPG, 2MB 이하. 만든 뒤 휴대폰 목록 크기(168x94)로 줄여 글자가 읽히는지 확인한다.
- 구현: `projects/<이름>/thumbnails.py`를 새로 쓴다(엔진의 `new_canvas`, `put`, `text_spr`로 1280x720 한 장을 그려 저장). 형식은 담당자가 준 참고 이미지를 따른다.
